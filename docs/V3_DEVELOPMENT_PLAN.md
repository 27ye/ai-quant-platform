## 4. 五项功能的可执行边界

### F1：本地自选

- 自选卡片放在现有个股工作台的紧凑区域；当前 `/` 会转到个股，`/home` 是品牌页，本版不改品牌首页和侧栏结构。
- 保存六位字符串代码、名称、加入时间；按代码去重，最多 20 只。代码保留前导零，顺序按加入时间固定。
- localStorage 使用独立带版本的 key。缺失或损坏数据不导致页面崩溃；过滤非法条目并提示恢复结果。
- 存储被禁用/写入失败时明确提示“本次未持久保存”，允许页面内继续使用；不能显示保存成功。
- 加入、移出和展示列表本身不额外请求行情；点击进入个股后允许正常页面请求，不要求整个导航零网络。
- 刷新/重开浏览器后恢复；同一浏览器跨标签页通过 storage 事件同步，不承诺跨设备。
- 冻结验收模式继续限制可打开股票；不能通过自选入口绕过已有模式限制。
- 首版不展示每只自选股的实时价格，不增加轮询和批量 Provider 调用。

### F2：AI 报告导出 Markdown

- 使用已加载的详情对象生成 Blob，下载后释放对象 URL；导出动作无额外请求。
- 正文各段、优缺点、报告 ID、股票、模式、关联回测、模型、创建时间、数据日期、来源、三个版本及 context_hash 都有确定映射。
- `data_as_of` 与实际行情结束日期分开标注；数据日期来自保存的上下文，缺失就写“未记录”，不能用今天日期补造。
- `legacy_missing` 明示“旧报告缺少上下文快照”；缺失值不能显示为 0。历史来源保留原值，另标明是在读取历史报告。
- 文件名仅使用校验后的代码、数字 ID 和 ISO 日期，例如 `ai-report-600519-123-2026-09-22.md`；不使用模型生成标题作为路径。
- 对外部正文中的 HTML/Markdown 控制字符进行适当转义，不拼入脚本、凭据或任意页面 HTML；保留可阅读的段落。
- 先完成 standard/V2 导出；F4 合入时只增加模式字段映射，不等待 F4 才开发。

### F3：同股票两个历史回测对照

- 从某股票的回测历史选两份不同记录，进入 `/backtests/compare?a=<id>&b=<id>`；校验正整数、重复 ID、跨股票 ID和缺失记录。
- 同股票翻页保留最多两个已选 ID；切换股票清空选择。选择条显示代码与 ID，用户可取消，不为跨页选择额外预取整份详情。
- 初次加载每个 ID 一次详情 GET；刷新重新读取允许。无行情/新闻/计算/LLM 请求；全局 health 等已有请求不算对照数据请求。
- 显示：ID、策略名称/版本、执行语义、请求与实际区间、预热、资金/成本/滑点/策略参数、来源与 C 输入快照哈希。
- 对照收益率、年化、回撤、夏普、胜率、交易次数；保留单位和 null。不把高胜率等同于较优，也不据不同窗口生成“赢家”。
- **首版一份结果一张图并排展示**。展示收益率时只做既有 `equity / initial_cash - 1` 换算，不重新计算金融指标；资金无效时不画虚假 0 曲线。
- 不裁剪成看似相同的窗口，不插值/前向填充日期；不同区间、资金、成本或语义有可见提示。
- 旧记录允许只比较已有摘要，缺失曲线/参数明确展示缺失。`c_result_exact=false` 保留旧精度提示，不伪装精确结果。
- 记录不存在、单侧失败、慢响应后切换 URL 都有独立状态；旧请求不得覆盖新选择。

### F4：AI 解读保存的回测

**依赖已保存结果，不依赖 MACD、新行情或最新指标。**

1. 请求仍为 `POST /api/v1/ai/analyze`；新增可选 `backtest_id`。省略为 standard；提供正整数为 custom_backtest；显式 null 或非整数拒绝，模式由服务端推导。
2. 在调用 LLM 前确认记录存在、属于 stock_code、为 v2_windowed，且精确结果与必要快照完整且可校验。首版拒绝不精确的旧 JSON 结果，避免悄悄升级旧记录质量。
3. 从 Repository 读取保存的 C 结果与来源；按明确白名单提取策略/算法版本、参数、区间、预热、执行假设、指标、初始权益、哈希与少量确定性曲线摘要。不透传整包到 Prompt，不复制全部日线和成交明细消耗上下文。
4. 不调用 Provider、News、默认评分或回测流水线；来源缺失写 unknown。生成报告只允许数据库读写与 LLM 请求。
5. 新增独立 `BacktestInterpretationContext`，保留旧 `AnalysisContext`。按模式和 context_schema_version 明确分派读取；未知版本、字段矛盾、哈希不符按数据损坏处理。
6. 保留现有 MySQL JSON 数值归一化规则：**提取 → 一次归一化 → 严格校验 → 同一对象用于 Prompt/哈希/入库**。原始 C 精确文本不改写；context_hash 与 c_data_hash 是不同对象的哈希，分别标注。归一化后的值不承诺与原始浮点逐位相等。
7. standard 继续使用原默认上下文与版本。custom 单独命名 Prompt/上下文版本（建议 `v3.backtest.1`）；输出结构未变时不无理由修改旧输出版本。
8. 尽量复用报告结构；custom 的 quant_score 固定为 null，不能把策略收益变成默认股票评分。模板将新闻段明确写为“未纳入新闻”；不展示当前股票多空判断。D 在第 1 天提供全部字段到页面标题的映射，A 审核。
9. 可核对的事实表由服务端保存字段确定并由页面直接展示；LLM 提供解释，不负责计算事实表。不承诺任意自然语言数字都自动精确，验收抽查有无虚构收益、新闻和建议。
10. 新报告包含 analysis_mode/backtest_id，关联 ID 不能替代独立上下文快照；重启后历史 GET 仍只读自身保存内容。
11. 沿用最多一次输出修复、失败不保存半份报告。按钮请求中禁用；不自动重试付费生成。手动再次生成允许产生新报告，首版不承诺服务端 exactly-once。

模式元数据建议：custom 的 data_as_of 使用所依据回测的保存时间；实际行情结束日期单独来自结果区间，created_at 是本次报告生成时间。三者在样例和页面中分别命名，不把旧回测当成当天市场观点。

### F5：MACD 多头策略

- 请求选择值建议 `ma_cross | macd`。ma_cross 映射现有 MA 实现，不改原有策略名/版本/数值；MACD 使用独立策略名称和算法版本。
- 参数建议沿用配置命名：`macd_fast_period`、`macd_slow_period`、`macd_signal_period`，默认 12/26/9；约束建议 `2 ≤ fast < slow ≤ 120`、`2 ≤ signal ≤ 120`。共同参数仅 initial_cash、transaction_cost、slippage，保持现有范围。
- 非整数周期、布尔、字符串、NaN/Infinity、显式 null、未知字段、另一策略专有字段均在取数前拒绝。类型和参数白名单随策略选择，不让客户端覆盖整个 QuantConfig。
- 为缩小范围，建议定义为目标仓位：有效 DIF > DEA 时为 1，否则为 0；相等时空仓。T 日收盘信号最早 T+1 开盘执行，可使用最后预热日信号决定窗口第一天开盘。此规则须如实命名，不能文档写事件型金叉而代码采用另一种初始持仓规则。
- 复用现有 EMA 算法；C 第 1 天冻结种子、adjust/min_periods、柱倍数、必需预热行数函数以及截取规则，附默认与边界样例。不能把“slow + signal”直接当作 EMA 已完全收敛的证明。
- 预热规则必须确定且版本化；B 按 C 的 required_warmup_rows 取数，C 决定实际消费窗口。输入快照、数据哈希覆盖实际预热与交易数据；不可直接沿用 MA 预热假设。
- 回测执行/成本/基准复用原引擎；必要时只提取内部共用执行函数，不做插件系统，不复制第二套资金核算。
- 参数化 MACD 不能修改默认配置、默认评分、默认 AI 或其他请求的状态。
- 固定样本可重复；手算短样本验证成交时点/成本；追加未来数据不改变已有时点信号和成交。大预热边界用充足的合成样本，不强求短交付包覆盖全部参数上限。
- 仍披露研究用简化成交模型，不以收益好坏判定功能合格。

### 5.1 回测请求矩阵

| 请求形态 | 约定 |
|---|---|
| strategy 省略，parameters 省略/对象/null | 完整保留 V2：分别为旧语义、窗口语义、40001 |
| strategy=ma_cross | parameters 与日期沿用 V2；不因新增选择字段改变旧行为 |
| strategy=macd，parameters 省略或 {} | 使用 MACD 默认参数，v2_windowed；要求明确 start_date/end_date |
| strategy=macd，自定义参数对象 | v2_windowed，参数按 MACD 白名单校验；要求明确起止日期 |
| strategy=null/未知值；参数对象或成员为 null；混用策略参数 | HTTP 400 / 40001，取数前失败 |

F5 使用明确日期减少新语义分支；旧 MA 请求的日期解析保持现状。B/C 同步更新 API、适配器、解析与执行函数签名，保留旧调用形式。新结果保存完整参数、策略和算法版本；历史 GET 不根据当前代码重算。

### 5.2 AI 请求与错误

示例仅表示拟新增请求，不代表已经支持：

```json
{"stock_code":"600519"}
```

```json
{"stock_code":"600519","backtest_id":123}
```

| 场景 | HTTP / 业务码 |
|---|---|
| 非法参数、跨股票关联 | 400 / 40001 |
| 回测不存在 | 404 / 40005 |
| 报告不存在 | 404 / 40006 |
| 历史回测合法但不满足解读条件 | 建议新增 422 / 40007，消息 backtest snapshot unavailable |
| 声称完整的新快照损坏或元数据矛盾 | 500 / 50002 |
| LLM 失败或修复后仍无效 | 沿用 50005 及现有 HTTP 映射 |
| 行情失败、目录未初始化 | 分别保持 502 / 50001、503 / 50006 |

40007 在本次代码核对中未占用；B/D 合契约时再次检查，统一更新 errors、API_SPEC、前端文案和测试。失败场景均证明没有成功报告记录；前四类请求错误不得调用 LLM。

列表与详情兼容增加 `analysis_mode: standard | custom_backtest`、`backtest_id: int | null`；列表仍不含完整上下文。第 1 天 D 交付新/旧报告及各失败响应的完整 JSON 样例，不把这份计划冒充最终 Schema。
