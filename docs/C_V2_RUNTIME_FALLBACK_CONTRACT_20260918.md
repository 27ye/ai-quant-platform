**C同意由D决策、B/D实现“东财失败后腾讯qfq兜底”的方向；以下是量化可复现性的实现边界。不是批准任意逐行拼接、来源等价或直接放行新SHA。**

## 对D的三个问题

1. **原九组签字**绑定85b7617及固定c-delivery-20260917包，作为该版本的历史验收仍有效。新Provider代码产生新SHA后必须复验受影响范围，不能写成新SHA自动获得旧签字。冻结包/旧快照不改写。
2. **不同次运行可由不同真实来源完成，但结果可能不同。** 输入价格、可选字段或元信息变化可改变输入哈希；OHLC微小变化也可能跨过均线/评分阈值。此前最大约0.004元仅是三股特定样本的观测值，不是未来误差上限。不能以“两位舍入相同”为由抹平四位数据差异。结论需注明实际来源、数据截至日、复权口径、规范化/派生规则及输入哈希；可复现以保存的实际输入快照为准，不靠重新在线取数。
3. **amount/turnover_rate=None可接受。** 当前MA策略与评分不使用这两列。C在冻结600519上仅将两列由null替换为固定数值，pipeline金融输出及V2金融结果不变，输入快照哈希按设计改变。不要补0冒充真实值。

## 必须对齐的实现细节

- **单次输入的一致性**：一次回测/评分/AI上下文应尽量来自同一来源、同一qfq响应。切源时刷新本次计算所需的完整预热+窗口，不能只把缺失尾部接到不同厂商/不同复权基准的旧前缀上并声称单源。历史qfq会重算，端点须确证是qfq，不能把未复权day静默当qfq。若保留混合窗口，需准确记录各段来源与范围并验证复权连续性；当前只有一个source字符串不够。只计算所需窗口，不要求为此清空历史库。
- **来源传递**：当前MarketDataService.get_query_provenance()返回StockService.provider_name，AKShareStockProvider固定映射为akshare。last_kline_source虽入stock_daily_sync.source，但只修改Provider字段未证明AI/缓存/历史展示正确。要验证live→缓存命中→保存报告→历史GET中保留实际厂商/端点来源，并把包装器名称与数据来源分开。不得把局部覆盖留下的旧区间误标成最后一次来源。若现有链路无法表达，应调整必要的B/D字段/传递逻辑，不能为“一文件改动”牺牲真实性。
- **change_pct**：同意腾讯按导出器的相邻qfq close派生，输出是小数收益率 `(close_t-close_prev)/close_prev`，100→101应为0.01；无前值则null。尽量在截取请求窗口之前计算，取得前一有效日再裁剪，避免随请求起点变化。现有_normalize_daily_kline对该列除100，复用时必须处理输入单位，不能把已经派生的小数再次除100。沿用B的4/2/6舍入规则，并验证POST当次与DB读回一致。
- **评分敏感性**：B“change_pct不影响金融结果”的表述需限定。MA回测不直接用此字段，但_score_volume直接使用其正负和阈值；C确定性探针在放量条件下把change_pct从+0.000001变为-0.000001，分项由20变0。这是合成边界示例，不是实测股票收益影响。需检验默认评分及AI默认上下文，不能只检验回测收益。
- **失败与日期**：保持主源严格校验、有限超时/重试、保留股票信息有效兜底；所有行情源失败仍50001，无效/空响应不写成成功。不能默认缓存已有数据就认定“实时门禁通过”。截至今日的日历行数包含今日交易日，但今日未开盘/未收盘时不能推断已应有完整日线；先明确完整交易日与当前日处理，缺数据如实返回，不能造数据或静默放宽完整性条件。
