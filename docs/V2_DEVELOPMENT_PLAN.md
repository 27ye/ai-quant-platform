## 1. V2 要交付的结果

用户能搜索并切换不同 A 股，查看真实日线、指标、评分和新闻；输入回测参数运行已有均线策略，查看曲线、交易记录并再次打开历史结果；生成 AI 分析后，可以按股票查询并重看历史报告。

“实时”在本版指**运行时从真实来源更新日线数据**，不是分时行情、逐笔报价或交易执行。“多股票”指支持多只股票的搜索、切换和逐只分析，不包含投资组合回测或全市场并发扫描。

| 优先级 | 本版交付 | 完成标志 |
|---|---|---|
| P0-1 | 实时多股票链路与数据状态 | 至少 3 只约定股票完成真实取数、MySQL 回读、页面展示；失败和过期状态可辨识 |
| P0-2 | 参数化单股票回测 | 可设置日期、初始资金、短/长均线周期、交易成本和滑点，结果对应实际输入 |
| P0-3 | 回测历史 | 结果、曲线、成交记录和参数保存；重启后可按 ID 重看，不重新计算 |
| P0-4 | AI 报告历史 | 新报告返回 ID 和时间；按股票分页查询、打开详情，不重新调用 LLM |
| P0-5 | 联合验收与交付记录 | 离线回归、真实 MySQL、实时多股票、浏览器操作四类证据分别记录 |
| P1，可后排 | 本地自选列表、报告导出、两个已保存回测结果的对照展示 | 只有 P0 完成且排期允许时再安排，不作为本版承诺 |

延续 Vue 3、FastAPI、MySQL、AKShare 和现有模块化单体。V2.0 不加入自然语言 Agent、RAG、自动选股、多策略优化、用户权限、实盘交易、分钟线或新市场。保持当前技术栈，本计划不要求新增依赖。

## 5. 开发前冻结的接口与存储契约

以下为拟定扩展，均尚未实现。产品 V2 不强制把 API 路径整体改成 `/api/v2`；保留 `/api/v1`，优先兼容扩展。第 1–2 天同步更新 `API_SPEC.md`、`DATABASE_DESIGN.md`、V2 对旧规范的适用说明，再交付 Schema 和 JSON 样例。

| 接口/契约 | 建议内容 | 主负责人 |
|---|---|---|
| `GET /api/v1/stocks/search` | 路径和数组响应保持不变，内部改为已同步股票目录搜索 | B |
| `GET /api/v1/stocks/{stock_code}/data-status`（拟新增） | 股票目录/行情截至日期、最后刷新时间、来源、模式、覆盖/新鲜度状态；状态与本次实际使用的数据一致 | B；A/D 消费 |
| `POST /api/v1/backtests` | 保留 stock_code 和日期；增加可选 parameters 对象，只接受 C1 白名单；省略时保持原默认行为 | B；C 提供规范 |
| `GET /api/v1/backtests`、`GET /api/v1/backtests/{backtest_id}` | 列表按股票/分页过滤；详情返回保存时的参数、指标、曲线、成交和数据元信息 | B |
| `POST /api/v1/ai/analyze` | 请求仍只传 stock_code；返回已有内容并兼容增加 report_id、created_at 等元数据 | D |
| `GET /api/v1/ai/reports`、`GET /api/v1/ai/reports/{report_id}` | 列表摘要与详情分开；详情返回保存时正文和元数据 | D |

公共规则：股票代码为 6 位字符串，金额/百分比使用既有单位；时间带明确时区，日期按交易日表示。列表建议 page 默认 1、page_size 默认 20/最大 100，按 created_at DESC、id DESC 稳定排序；无结果返回空列表，未知 ID 返回 HTTP 404，资源不存在的新业务码由 B/D 在契约 PR 中定义，不能复用“股票不存在”混淆语义。

新鲜度必须按实际可确认的交易日/覆盖证据判断，不能以自然工作日代替交易日历。合法缓存可以复用，数据源失败不能悄悄转成冻结模式。数据状态接口不能单独证明报告来源，回测/报告保存时仍需携带自身数据快照元信息。

参数回测建议在 1 次请求内限制为 1 只股票、1 组参数、至多 5 年用户区间。为兼容旧调用，按 parameters 字段是否显式出现区分执行语义，建议在 M0 冻结以下矩阵：

| 请求形态 | 执行语义 | 必须返回/保存 |
|---|---|---|
| 省略 parameters，包括只传 stock_code/日期 | `v1_legacy`：保持当前默认计算和区间行为 | semantics_version、实际执行区间和完整默认配置 |
| 显式 `parameters: {}` | `v2_windowed`：使用默认金融参数，但按所选区间零初始持仓，区间前数据仅预热 | semantics_version、实际区间、预热区间和完整生效参数 |
| 显式非空 parameters，包括只改 initial_cash | `v2_windowed`：白名单内覆盖参数，其余用默认值；沿用上述新窗口语义 | 同上 |
| 显式 `parameters: null` 或未知参数 | 参数错误 40001，取数前拒绝 | 不生成成功记录 |

新窗口请求未传日期时，B 先解析为明确的默认日历区间，再补取预热数据；解析后的实际区间必须展示和保存。A 的新表单始终显式传 parameters 和选定日期。B 的 Schema 保留字段存在性，不能用默认空对象抹掉缺省与显式空对象的区别。C 提供两套语义的回归测试，B 不把任意 QuantConfig 字段整包透传；新增响应和历史快照保存 semantics_version。

**存储方案：**复用 backtest_result、ai_analysis，在增量迁移中添加版本化 JSON 结果/上下文快照及必要元数据。回测快照保存实际计算输入（含预热）、完整结果、参数、算法版本和数据哈希；AI 快照保存当时实际送入分析的结构化上下文、版本和来源。JSON 数值精度策略在 B/C 契约中明确，结果回读应保持约定精度，不能用旧摘要 DECIMAL 列重新拼装曲线。

行情历史可能随 qfq 刷新变化，因此仅保存 stock_code、日期或哈希不足以复现。历史详情读取已保存快照，不用当前 stock_daily 或当前 LLM 覆盖旧结果。旧 V1 记录缺字段时提供兼容详情和“历史快照缺失”标记；新旧记录都要有测试。

迁移由 B 统一实现，D 提供 AI 字段并评审。既有 create_all 不能替代 ALTER/数据迁移；迁移部分失败不得提前记录成功版本，重跑须可恢复。先在独立 V1 测试库证明升级与旧版读取兼容，保留备份恢复步骤，不自动删除旧数据。
